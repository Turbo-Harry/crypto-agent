## 2. 目标定义与「好」的标准（继承 v0.1 §2，业界规范 S1-S5 不变）

> S1 Pardo（[书目](https://discover.libraryhub.jisc.ac.uk/search?q=9780470128015&rn=1&for=sth#1)）：净利/PF/回撤/walk-forward/≥30 笔。
> S2 Tharp（[TradesViz](https://www.tradesviz.com/glossary/system-quality-number/)、[QuantStrategy.io](https://quantstrategy.io/blog/system-quality-number-sqn-evaluating-your-strategys/)）：expectancy、SQN=√N·mean(R)/std(R)，≥2.5 为好。
> S3 López de Prado（[PBO](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2326253)、[Deflated Sharpe](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551)、[pypbo](https://github.com/plaintext-capital/pypbo)）：PBO<0.3 / Deflated SR≥1、试验日志、minBTL。
> S4 MAE/MFE（[FTMO](https://ftmo.com/en/blog/how-can-you-improve-your-stop-loss-and-take-profit/)、[MQL5](https://www.mql5.com/en/articles/23245)）。
> S5 agent 评估 = S1/S3 复用（决策重放对照）。

## 5. 自质疑与打磨

### 5.1 v0.1 质疑轮遗留项答复（Q1/Q3/Q6 —— 本版必须回答）

**Q1（低成本样本扩充是否引入？）→ 裁定：引入「影子重放集」，但只给证伪权，不给证实权。**

- 机制：用历史 1H K 线重放 `scan_signal` 生成假设性交易序列（与现有 backtest/ 设施复用）；结果标注 `source=replay`，与实盘样本严格分离。
- **证伪权**：若重放集上策略 SQN < 0 或 MAE 分布否决止损假设 → 提前停调参/进入退役评估（防继续浪费时间）。
- **无证实权**：重放结果**不能**用于宣称改进、不能触发自动参数变更（防止把回测当实盘——S3 管束，历史重放=多重检验高风险源）。
- 实盘 30 笔门槛不变。新增假设 A6（重放证伪力）追踪其有效性。

**Q3（"自证一次"是循环论证）→ 裁定：接受质疑，改为「一致性初筛 + 独立验证」两级机制。**

- 一级·一致性初筛（本笔，**不做评分**）：教训生成时记录归因方向（如"止损太紧"→ 预期本笔因止损距离过近亏损）。本笔结果若与归因方向一致（确实止损出场且 MAE 触顶）→ 教训标记 `candidate`（可被采纳）；不一致 → 标记 `dubious`（不进采纳池，仅留存观察）。
- 二级·独立验证（后续交易，唯一评分来源）：`candidate` 教训可被决策层**低权重参考**（只写入决策 reason 文案，**不改变任何参数**）；被采纳后由**后续独立交易**结果 ±10 分验证；3 次独立验证后按分数晋升 trusted/discarded（沿用 ScoredExperience 既有规则）。
- 效果：死锁打破（unverified→candidate→被采纳→被验证→晋升），且无循环论证（评分全部来自生成该教训之后的交易）。

**Q6（权责矩阵缺失）→ 见 §7。**

## 6. 零回归约束（用户硬性要求："保证修改的内容不会影响到以前的逻辑"）

### 10.3 收敛判定标准（量化，业界退出准则式）

宣布"已收敛"必须**同时**满足：
1. 连续 **3 轮**全量回归零新增失败（当前：1 轮）；
2. 体检 H1-H9 连续 **48 小时**全绿（当前：9/9 起步）；
3. 缺陷到达率连续 **48 小时归零**（按 §10.1 台账类别统计）；
4. 生产浸泡 48h：engine_errors 零新增、无熔断误报、账本对账一致。
达到前，系统定位 = 「审计收敛、浸泡观察中」——诚实地不宣布收敛。

### 10.4 诚实边界
机制把"发现"从人眼抽查变成定时自动+套件内置，但**"保证收敛"仍是统计意义上的**：
机制能保证"已知不变量被持续检验"，不能保证"不存在未知缺陷"。因此 Phase 1-5
的 backlog（DEF-4/5/7/9）与未读代码面（约 57% 全仓）仍是已知的未检验面——
它们要么进体检清单，要么进 backlog，绝不允许存在于"既没检查也没记录"的盲区。
