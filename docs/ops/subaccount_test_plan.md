# R1-13 — OKX 子账户隔离沙盘实测计划

> 目的：验证 OKX 模拟盘（demo trading）是否支持子账户 + 独立 API key。
> 若支持 → R3-2 子账户隔离方案（套利/方向仓分账户）可实施，是跨进程账户串扰的根治项。
> 若不支持 → 维持 R1-6 同 posSide 拒绝 + R1-12 所有权账本 + 临界区锁的组合方案。

## 测试步骤

1. 登录 OKX 模拟盘 Web 界面 → 账户 → 子账户管理：
   - 能否创建子账户？（demo 环境常限制此功能）
   - 记录：能否创建、创建数量上限。

2. 若可创建子账户：
   - 为子账户创建**独立 API key**（模拟盘模式），确认 demo 环境是否支持子账户 key。
   - 记录 key 的权限模型（只读/交易/提现）。

3. 资金划转测试：
   - 主账户 → 子账户划转 100 USDT（模拟资金）。
   - 确认子账户余额独立显示、与主账户互不可见。

4. 独立持仓验证（核心）：
   - 子账户 A 开 BTC-USDT-SWAP 空 0.01（模拟套利腿）。
   - 主账户开 BTC-USDT-SWAP 空 0.01（模拟方向仓）。
   - `fetch_positions` 分别查询：断言两个账户**各显示 1 个仓位**（不合并）。
   - 主账户平仓 → 断言子账户仓位不受影响（这是 R1-12 误平的根因场景）。

5. 杠杆独立验证：
   - 子账户 A 设 BTC 杠杆 1x、主账户设 3x → 互相查询断言互不影响。

## 判定标准
- 全过 → 实施 R3-2：okx_config.json 拆分 sub_account 配置（两套 key），
  trading_main 用套利 key、directional_trader 用方向 key，独立保证金/爆仓线。
- 任一失败 → 回退组合方案（R1-6 + R1-12），并在笔记标注"子账户不可用，组合方案为长期方案"。

## 风险提示
- 子账户迁移期间两进程应停跑，避免过渡期共享账户继续并发。
- 迁移后旧主账户持仓归属需人工盘点一次。
